## langchain-agensgraph 0.3.0

On the [`agensgraph-python`](https://pypi.org/project/agensgraph-python/) 2.0 driver, with retrievers, a text2cypher chain and a LangGraph store added.

```bash
pip install langchain-agensgraph
```
OR
```bash
pip install "agensgraph-ai[langchain]"
```

- `AgensEngine` is a driver connection pool, sync and async, shared by every component built on it.
- `query()` returns the driver's `Vertex`, `Edge` and `Path` values, with the label, the id and the properties kept apart. `query_many()` runs a burst of reads without waiting for each in turn.
- A `str` parameter is sent as text. `json.dumps(...)` around a string parameter is no longer needed, and has to go: a JSON-encoded string now matches nothing.
- `AgensgraphVector` is on the driver's vector types and indexes. `filter_properties` names the metadata properties a search filters on, and they get indexes.
- Three `BaseRetriever`s, each one server round trip: `AgensVectorRetriever`; `AgensGraphContextRetriever`, which fetches each seed's neighbourhood within `expand_by_hops` in the seed search's own statement, with `render_graph_context` to format it for a prompt; and `AgensText2CypherRetriever`, where a model writes the Cypher and the server contains it, with `max_retries` and `retry_on_empty` feeding a failure back for a corrected attempt.
- `AgensCypherQAChain` answers a question with generated Cypher run in a read-only transaction, and `create_cypher_tool` gives an agent the same. The schema the model reads names the graph's property indexes (`include_indexes`), `examples=` adds few-shot pairs, `DIALECT_EXAMPLES` is a curated set of them, and `evals/text2cypher/` scores generated Cypher by executing it.
- `AgensStore`, a LangGraph `BaseStore` whose filters and namespace search run in the database. `AgensSaver` / `AsyncAgensSaver` complete the thread lifecycle with `prune`, `copy_thread` and `delete_for_runs`, and page the history reads.
- `log_queries()` reports every statement a block of code ran, and how long each took.
- Fixed: a store search filter ignored its comparison operators; `prune` deleted the checkpoints a delta channel rebuilds from; `LLMGraphTransformer` wrote duplicate nodes when an entity type differed only in case; `AgensChatMessageHistory` appends and windowed reads grew with the length of the history; `AgensQueryException` read `details` while every raise wrote `detail`.
- AgensGraph 2.17 or later; an older server is refused at connect. Python 3.11 to 3.14.

## llama-index-agensgraph 0.3.0

`AgensPropertyGraphStore` and `AgensgraphVectorStore` on the driver, with the two query paths that did not work rebuilt.

```bash
pip install llama-index-agensgraph
```
OR
```bash
pip install "agensgraph-ai[llama-index]"
```

- Each node is stored on a label named after its type, and the embedding has its own column, indexed on the labels that hold one. `bulk_ingest()` skips the index during a load and builds it after.
- A query embedding is sent as a vector, and a list of ids is bound once rather than written out as one condition per id.
- The search mode a query asks for is the one that runs.
- Generated Cypher runs in a read-only transaction.
- The schema is read from the catalogs; nothing is installed in the database.
- A failed statement is rolled back, so the connection stays usable.
- The async methods are implemented instead of blocking the event loop.
- A label name over 63 bytes is shortened and given a hash of the whole name, since the server truncates it.
- `AgensEngine`, an opt-in connection pool shared across stores.
- AgensGraph 2.17 or later; an older server is refused at connect. Python 3.11 to 3.14.

## lightrag-agensgraph 0.3.0

The four storages — `AgensgraphStorage`, `AgensgraphVectorStorage`, `AgensgraphKVStorage` and `AgensgraphDocStatusStorage` — on the driver, with one connection pool per graph.

```bash
pip install lightrag-agensgraph
```
OR
```bash
pip install "agensgraph-ai[lightrag]"
```

- Requires `lightrag-hku` 1.5.6 (the `>=1.5.6,<1.6` range). `AgensgraphDocStatusStorage` implements the scheduling API 1.5.6 drives it through, and upgrades its table in place.
- Each relation is stored once, and edges are read by graph id.
- Vectors are written in batches and in binary, a search runs on the HNSW index, and `bulk_ingest()` loads a dataset with the indexes rebuilt afterwards.
- The demos are rebuilt on the new stores, and the README says how the data is kept.
- AgensGraph 2.17 or later; an older server is refused at connect. Python 3.11 to 3.13.

## cognee-agensgraph 0.3.0

`AgensgraphAdapter` and `AgensgraphVectorAdapter` on the driver.

```bash
pip install cognee-agensgraph
```
OR
```bash
pip install "agensgraph-ai[cognee]"
```

- Requires cognee 0.2 (the `>=0.2.1,<0.3` range). 0.3 changed the graph interface.
- Each DataPoint class is stored on its own label, in lower case, so Cypher written by a user or a model finds it as `Entity`, `entity` or `"entity"` alike. A graph written by 0.2.0 kept every node on one label and is not readable by this layout; drop it and run `cognify` again.
- The graph is read without converting rows, and the metrics return all ten of them.
- Embeddings are sent in binary, a nearest search runs on the HNSW index, and `bulk_ingest()` loads a collection with the index rebuilt afterwards.
- `query()` is read-only by default. `query_read_only = False` lets a statement written by a user or a model write through it.
- The demos are rebuilt on the new layout.
- AgensGraph 2.17 or later; an older server is refused at connect. Python 3.11 to 3.13.

## mcp-agensgraph 0.3.0

The four packages release together, on FastMCP 3 and the driver.

```bash
pip install "agensgraph-ai[mcp]"
```

- A read runs in a `READ ONLY` transaction, which is where the guarantee lives: the database refuses a write whatever the text looked like. `--read-only` does not register the write tool at all.
- A statement is a graph statement and only that. SQL behind `EXPLAIN`, a query definition or a lead word Cypher shares with SQL is refused.
- A server refuses to start as a role that can run a command on the database host — a superuser, or a member of `pg_execute_server_program` — unless `--allow-server-programs` accepts it. Graph DDL from a write needs `--allow-graph-ddl`.
- A response is bounded without a tokenizer. `mcp-agensgraph-common[tokens]` installs tiktoken to count exactly rather than estimate.
- The connection string is composed rather than interpolated, and nothing ships a password.
- AgensGraph 2.17 or later; an older server is refused at connect. Python 3.11 or later.

### mcp-agensgraph-cypher

```bash
uvx mcp-agensgraph-cypher
```

- Performance tools: `explain_agensgraph_cypher` plans a statement, and runs it under `analyze` inside a read-only transaction; `recommend_property_indexes` reasons from the plan and the label catalogs, names the shapes that cannot reach an index — `STARTS WITH`, and an `IN` list bound as a parameter — and says that its advice is reasoned, not measured; `agensgraph_health` reports cache hit ratio, unused indexes, vacuum backlog, connection use and the optional extensions; `top_cypher_queries` reads `pg_stat_statements`.
- `get_agensgraph_schema` asks the driver for what it already knows about a graph.

### mcp-agensgraph-memory

```bash
uvx mcp-agensgraph-memory
```

- A name identifies one entity and a relationship identifies one edge, held under eight callers writing at once.
- `find_memories_by_name` bounds its response and reports the names it dropped.
- `--adopt-existing-graph` serves a graph this server did not make.

### mcp-agensgraph-data-modeling

```bash
uvx mcp-agensgraph-data-modeling
```

- `get_constraints_cypher_queries` returns a list, one whole statement per item, since a label may contain the separator a consumer would split on.
- A generated label or property name is quoted where it is placed in the statement.

### mcp-agensgraph-common

The shared core the servers above depend on: configuration, connection handling, the statement policy, result shaping and transport. Installed automatically; not intended for direct use.

## agensgraph-ai 0.3.0

One name that installs any combination of the integrations. It ships no code of its own.

| Install | Package | Then import |
| --- | --- | --- |
| `pip install "agensgraph-ai[langchain]"` | `langchain-agensgraph` | `langchain_agensgraph` |
| `pip install "agensgraph-ai[llama-index]"` | `llama-index-agensgraph` | `llama_index_agensgraph` |
| `pip install "agensgraph-ai[lightrag]"` | `lightrag-agensgraph` | `lightrag_agensgraph` |
| `pip install "agensgraph-ai[cognee]"` | `cognee-agensgraph` | `cognee_agensgraph` |
| `pip install "agensgraph-ai[mcp]"` | `mcp-agensgraph-cypher`, `-memory`, `-data-modeling` | run as commands |
| `pip install "agensgraph-ai[all]"` | everything above | |

They compose: `pip install "agensgraph-ai[langchain,lightrag]"` installs both.

- There is no `agensgraph_ai` module. Each name in brackets is a shortcut to the real package, which you import under its own name.
- Installing a package directly is equivalent, since `pip install langchain-agensgraph` and `pip install "agensgraph-ai[langchain]"` produce the same environment. This is a convenience, not a layer.
- **Name at least one integration.** `pip install agensgraph-ai` on its own installs nothing, and a misspelled name installs nothing either; `pip` warns about that, `uv` does not.
- `[mcp]` is for hosting a server yourself over HTTP or SSE. An MCP client normally launches the servers with `uvx`, which installs nothing.
- Every extra requires 0.3 of its package and carries a lower bound only, so an integration can release without a release here. Python 3.11 or later.
