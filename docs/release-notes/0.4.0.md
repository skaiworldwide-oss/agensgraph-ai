## Security advisory

In langchain-agensgraph 0.3.1, the QA chain and the text2cypher retriever ran model-written Cypher inside `agensgraph-python` 2.0.0's `read_only_transaction()`, which `…; COMMIT; …` escaped, so a model could write to or drop the graph. Upgrading the driver to 2.1 closes it under 0.3.1 and under the other 0.3.1 integrations; langchain-agensgraph 0.4.0 requires 2.1. The full advisory is in the [`agensgraph-python` 2.1.0 release](https://github.com/skaiworldwide-oss/agensgraph-python/releases/tag/v2.1.0).

## langchain-agensgraph 0.4.0

A rewrite on [`agensgraph-python`](https://pypi.org/project/agensgraph-python/) 2.1 that runs on AgensGraph 2.14.1 and later. It changes the 0.3 API; [CHANGELOG.md](https://github.com/skaiworldwide-oss/agensgraph-ai/blob/main/langchain/CHANGELOG.md) lists each removed or renamed name with what replaces it.

```bash
pip install -U langchain-agensgraph
```
OR
```bash
pip install -U "agensgraph-ai[langchain]"
```

- AgensGraph 2.14.1 or later; 0.3 needed 2.17. The whole suite runs against 2.14.1, 2.15.0, 2.16.0, 2.17.0, 2.18.4.0 and 2.18.6.1 on every change. Python 3.11 to 3.14.
- Model-written Cypher runs only through `AgensGraph.query_untrusted`: the text is checked before it is sent, then run as a role made for it (`untrusted_conninfo`), in a read-only transaction that is always rolled back. `allow_dangerous_requests=True` is a required acknowledgement, and writes need `allow_writes=True`.
- `langchain_agensgraph.roles` prints the SQL for the roles the package expects: `app_rw` for the application, `llm_ro` for model-written reads and `llm_rw` for model-written writes.
- `AgensEngine` pools connections by kind: application, maintenance, untrusted, writer. Components handed one conninfo string share an engine, and `engine.transaction()` is a transaction every call through the engine joins.
- Agent state is readable from Cypher: `cypher_subquery()` on `AgensChatMessageHistory`, `AgensStore` and `AgensSaver` (with `queryable_channels`). Chat history, checkpoints and the store live in plain tables in `"<graph>_store"`.
- Vector store: hybrid search with `fusion`, `fusion_weights` and `rank_constant`, `hybrid_search_with_details`, `delete(filter=)`, `search_with_embeddings`, `build_index`, `index_status`, `clear` and `drop`. `*_with_score` returns the raw distance.
- `AsyncAgensStore`, a store for an event loop.
- The QA chain adds `allow_writes`, `return_direct`, `include_types`, `exclude_types`, `use_function_response`, `cypher_llm_kwargs`, `qa_llm_kwargs`, `schema="frozen"` and a correction loop (`max_retries`). `LLMGraphTransformer` adds relationship triples, `relationship_properties`, property whitelists, `additional_instructions`, `ignore_tool_usage`, `max_concurrency` and `on_error`.
- `graph_name` is required everywhere and `create_graph` is False everywhere. `AgensGraph(engine, graph_name="name")` replaces `AgensGraph("name", conf)`.
- `langgraph` is an extra: `pip install "langchain-agensgraph[langgraph]"`. pgvector 0.8.0 or later.

## agensgraph-ai 0.4.0

```bash
pip install -U "agensgraph-ai[all]"
```

- `[langchain]` requires `langchain-agensgraph` 0.4, so upgrading `agensgraph-ai` upgrades it. The other extras still require 0.3 of their package. Every extra carries a lower bound only.
- The README gives AgensGraph 2.14.1 or later for LangChain and 2.17 or later for the others, and the driver each runs on.

**Full Changelog**: https://github.com/skaiworldwide-oss/agensgraph-ai/compare/v0.3.1...v0.4.0
