## langchain-agensgraph 0.2.0

A ground-up modernization for LangChain 1.x and AgensGraph 2.17.

```bash
pip install langchain-agensgraph
```
OR
```bash
pip install "agensgraph-ai[langchain]"
```

- Targets `langchain-core` 1.x, with **no dependency on the archived `langchain-community`**: `GraphStore`, `GraphDocument` and `DistanceStrategy` are vendored locally.
- Full **async** surfaces on `AgensGraph` and `AgensgraphVector`: `aquery`, `asimilarity_search`, `aadd_texts`, `adelete`, `aget_by_ids`, `aclose`.
- **`AgensEngine`**: a shareable `psycopg` connection pool, sync and async. Pass `engine=` to share one pool across a graph store and several vector stores, so concurrent requests stop serializing on a single connection.
- **`AgensSaver` / `AsyncAgensSaver`**: a LangGraph `BaseCheckpointSaver` that persists agent state to the graph, so threads resume across restarts.
- **`AgensChatMessageHistory`**: a session's messages as an ordered chain of vertices, with per-session isolation and an optional `window`.
- **`LLMGraphTransformer`**: text-to-graph extraction through any chat model's `with_structured_output`, feeding straight into `add_graph_documents`.
- `add_graph_documents` runs in a single transaction, so a partial failure rolls back without leaving orphan nodes.
- `delete`, `get_by_ids`, `effective_search_ratio` over-fetch, and `batch_size`/`embed_batch_size` for production ingest.
- The internal system id moved to `__id__`, so user metadata `"id"` round-trips intact and `Document.id` is populated on retrieval.
- Typed `IndexConfig` (HNSW `m` / `ef_construction`, IVFFlat `lists`) and `HybridSearchConfig` (reciprocal rank fusion constant, per-modality weights).
- Schema introspection uses the `meta` extension when present, falling back to catalog scans on older versions; multi-label nodes and NULL-safe type detection.
- `enhanced_schema=True` samples example property values into the schema for better Text2Cypher prompting.
- Connection lifecycle: `close()` / `aclose()`, sync and async context managers, and `application_name` tagging for `pg_stat_activity`.
- Query `timeout` per instance and per call, and a `sanitize` flag that strips oversized list properties from results.
- Passes LangChain's standard `VectorStoreIntegrationTests` conformance suite.
- Python 3.10 to 3.14.
- Fixed: the `IVFFLAT` enum value was `"IVFLLAT"`, so pgvector rejected the DDL.
- Fixed: stray `print("DEBUG: ...")` calls replaced with `logger.debug`.
- Fixed: `_format_properties` now escapes apostrophes and backslashes.

## llama-index-agensgraph 0.2.0

```bash
pip install llama-index-agensgraph
```
OR
```bash
pip install "agensgraph-ai[llama-index]"
```

- **`AgensPropertyGraphStore.vector_query` works.** It hard-coded a 3-dimension embedding cast and ordered by a fixed literal vector, so results ignored the query embedding and errored at any other dimension. It now uses the configured `vector_dimension` consistently and ranks by the actual query embedding, backed by the HNSW index.
- **Metadata-filtered vector search** on both `vector_query` and `AgensgraphVectorStore.query`, translated into fully parameterized, injection-safe Cypher. All 14 `FilterOperator` values are supported: `EQ`, `NE`, `GT`, `GTE`, `LT`, `LTE`, `IN`, `NIN`, `CONTAINS`, `TEXT_MATCH`, `TEXT_MATCH_INSENSITIVE`, `ANY`, `ALL`, `IS_EMPTY`, with `AND` / `OR` / `NOT` and nested filter groups.
- **Hybrid search.** `AgensgraphVectorStore(hybrid_search=True)` fuses HNSW semantic search with full-text keyword search by reciprocal rank fusion; each modality is queried against its own index, so both stay index-backed.
- **AgensGraph-dialect Text2Cypher.** A default `text_to_cypher_template` that knows the storage model (every node on a single `"__Node__"` label, entity type held in a `labels` list) and avoids Neo4j-only syntax, so `TextToCypherRetriever` generates runnable Cypher out of the box.
- **Indexed type filter.** Each node also stores its primary type in a btree-indexed `__type__` scalar, so a type-scoped query is an index scan rather than a jsonb membership scan over `labels`.
- **Lazy schema introspection.** `refresh_schema=False` defers the O(N) schema scan to the first `get_schema()` / `get_schema_str()` call, so opening a large existing graph is instant.
- **Node management** on `AgensgraphVectorStore`: `get_nodes(node_ids, filters)`, `delete_nodes(node_ids, filters)` and `clear()`, plus `aget_nodes` / `adelete_nodes` / `aclear`.
- **Richer `enhanced_schema=True`**: numeric properties get `min` / `max` / `distinct_count`, list properties get `min_size` / `max_size`, and others get example values plus `distinct_count`.
- **`AgensEngine`**: an optional connection pool shared across stores.
- Fixed: entity embeddings are persisted on `upsert_nodes` even when the entity has no source chunk.
- Fixed: `get(ids=[])` returns nothing instead of the whole graph.
- Fixed: depth-1 `get_rel_map` uses a fixed pattern, AgensGraph's variable-length edges being far slower.

## lightrag-agensgraph 0.2.0

```bash
pip install lightrag-agensgraph
```
OR
```bash
pip install "agensgraph-ai[lightrag]"
```

0.1.0 shipped the graph store alone. 0.2.0 makes AgensGraph serve **all four** of LightRAG's storage roles, so one database replaces a graph DB, a vector DB, a key-value store and a status store.

- **`AgensgraphVectorStorage`**: entity, relation and chunk embeddings in `pgvector` HNSW tables.
- **`AgensgraphKVStorage`**: documents, chunks and the LLM cache in a JSONB table.
- **`AgensgraphDocStatusStorage`**: the ingestion pipeline in an indexed status table.
- **Shared async engine**: one pool behind all four storages.
- Parameterized SQL templates throughout, replacing string interpolation.
- The graph store is isolated per workspace.
- Indexed the vector delete paths and the doc-status sort keys.
- Graph-store correctness and performance work carried over from the modernization.
- Poetry to hatchling, Python 3.10+.

## cognee-agensgraph 0.2.0

```bash
pip install cognee-agensgraph
```
OR
```bash
pip install "agensgraph-ai[cognee]"
```

One AgensGraph database backs both of cognee's stores: the knowledge graph (`GRAPH_DATABASE_PROVIDER=agensgraph`) and the embeddings (`VECTOR_DB_PROVIDER=agensgraph`).

- **`AgensgraphVectorAdapter`**: implements cognee's `VectorDBInterface` over `pgvector` HNSW cosine, so AgensGraph can be the vector store as well as the graph store.
- **`cognify` runs end to end** with AgensGraph vectors. The adapter implements cognee's indexing hooks (`create_vector_index`, `index_data_points`), which previously raised `AttributeError`.
- **Fixed a quadratic ingest.** Node lookups and the MERGE key used the `id` property while the only index was on a different label and property, so every lookup was a sequential scan. A `base_id_idx ON "__Node__" (id)` index now backs both; roughly 5000 nodes and 5000 edges load in about 1.2s.
- **Batched `add_edges`**: UNWIND-batched per relationship type instead of one query per edge. `name` is indexed and used by nodeset retrieval, which was a sequential scan.
- **Shared async connection pool**: one refcounted pool opened once per process and reused by both adapters, with `graph_path` reapplied per checkout rather than per query.
- Fixed: `add_node`, `has_node`, `has_edge`, `get_neighbors` and `get_disconnected_nodes` were all broken: bad parameter binding, missing awaits, undefined variables, calls to methods that did not exist, invalid Cypher.
- Poetry to hatchling, Python 3.10+.

## mcp-agensgraph 0.2.0

`All three servers into an environment you control`
```bash
pip install "agensgraph-ai[mcp]"
```

Model Context Protocol servers for AgensGraph, ported from the Neo4j MCP servers and retargeted at AgensGraph. All three servers support `stdio`, `http` and `sse` transports, and take their connection from `AGENSGRAPH_*` environment variables or CLI flags.

### mcp-agensgraph-cypher

```bash
uvx mcp-agensgraph-cypher
```

- `read-agensgraph-cypher`: run a read query, with `params`, and `limit` / `offset` paging that returns `next_offset`.
- `write-agensgraph-cypher`: run an update query with `params`.
- `get-agensgraph-schema`: introspect labels, relationship types and properties.
- `--read-only` mode, rejecting writes outright.
- `--token-limit` bound on result size, so a large result cannot flood the context.
- `--namespace` support for exposing multiple graphs from one client.

### mcp-agensgraph-memory

```bash
uvx mcp-agensgraph-memory
```

Persistent knowledge-graph memory across sessions: entities as `Memory` nodes with a name, type and observations, joined by typed `Relationship` edges.

- `read_graph`: the whole memory, bounded by `limit`.
- `search_memories`: match against names, types and observations.
- `find_memories_by_name`: fetch specific entities.
- `create_entities`, `delete_entities`.
- `create_relations`, `delete_relations`.
- `add_observations`, `delete_observations`.

### mcp-agensgraph-data-modeling

```bash
uvx mcp-agensgraph-data-modeling
```

Design a graph schema before any data exists. Needs no database connection.

- Model creation: define nodes, relationships and properties against explicit schemas.
- Validation: `validate_node`, `validate_relationship`, `validate_data_model` for structural integrity.
- Cypher generation: node and relationship ingest queries, plus constraint queries.
- Mermaid diagrams for visualization.
- Arrows.app import and export (`load_from_arrows_json`, `export_to_arrows_json`).
- Seven pre-built example models: patient journey, supply chain, software dependency, oil and gas monitoring, fraud/AML, health insurance fraud.
- Guidance on the ingest order that avoids deadlocks.

### mcp-agensgraph-common

The shared core the servers above depend on: configuration, connection handling, result shaping, safety checks and transport. Installed automatically; not intended for direct use.

## agensgraph-ai 0.2.0

One name that installs any combination of the integrations. It ships no code of its own.

| Install | Package | Then import |
| --- | --- | --- |
| `pip install "agensgraph-ai[langchain]"` | `langchain-agensgraph` | `langchain_agensgraph` |
| `pip install "agensgraph-ai[llama-index]"` | `llama-index-agensgraph` | `llama_index_agensgraph` |
| `pip install "agensgraph-ai[lightrag]"` | `lightrag-agensgraph` | `lightrag_agensgraph` |
| `pip install "agensgraph-ai[cognee]"` | `cognee-agensgraph` | `cognee_agensgraph` |
| `pip install "agensgraph-ai[mcp]"` | `mcp-agensgraph-cypher`, `-memory`, `-data-modeling` | run as commands |
| `pip install "agensgraph-ai[all]"` | everything above | |

They compose: `pip install "agensgraph-ai[langchain,lightrag]"` installs both.

- There is no `agensgraph_ai` module. Each name in brackets is a shortcut to the real package, which you import under its own name.
- Installing a package directly is equivalent, since `pip install langchain-agensgraph` and `pip install "agensgraph-ai[langchain]"` produce the same environment. This is a convenience, not a layer.
- **Name at least one integration.** `pip install agensgraph-ai` on its own installs nothing, and a misspelled name installs nothing either; `pip` warns about that, `uv` does not.
- `[mcp]` is for hosting a server yourself over HTTP or SSE. An MCP client normally launches the servers with `uvx`, which installs nothing.
- Each entry carries a lower bound only, so an integration can release without a release here. No upper bound is set on Python either, so each keeps the range its own package supports.
